CapTale

A desktop Raylib game organized as a lobby-driven hub with city mini-games, shared player resources, and a state-based runtime flow.

4+1 View Model

Logical View

CapTaleSystem controls the application state. Cap stores player resources. Lobby routes the player into scene modules. The main city scenes are CustomCity, PongCity, CarCity, ATMCity, EarnCity, EnergyCity, and SpaceShooter. MessageManager supports user feedback, while Timer handles time-based behavior.

Development View

The project is organized around a single main.cpp entry point and a set of headers in headers/. Core files include cap.h, lobby.h, message.h, customCity.h, pongCity.h, carCity.h, atmCity.h, earningCity.h, energyCity.h, spaceShooter.h, sprites.h, custom_timer.h, settings.h, and spaceShooterSettings.h.

Process View

The runtime follows a single game loop. Each frame handles input, updates the active scene, processes collisions or timers, and renders the current screen. CapTaleSystem switches the active scene based on lobby selection or return-to-lobby signals from city modules.

Physical View

The system runs locally on a Windows desktop as a native Raylib-based C++ executable. All rendering, input, audio, and persistence occur on the same machine using local assets and the save file characterData.txt.

Scenarios

  • Entering a city from the lobby, paying any required token cost, and starting the selected scene.
  • Playing a city mini-game such as Pong, Car City, Earn City, Energy City, or Space Shooter.
  • Managing tokens and energy through ATM conversion, item collection, and lobby movement.
