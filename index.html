Academic Software Design Report

CapTale

A desktop Raylib game organized as a lobby-driven hub with city mini-games, shared player resources, and a state-based runtime flow.

Pong Game Flow

Code-aligned flow for PONG_CITY entry, mode selection, gameplay updates, pause, and exit.

sequenceDiagram actor Player participant CapTaleSystem participant PongCity participant Ball participant Paddles as Player/Ai Paddles Player->>CapTaleSystem: Enter Pong room from Lobby CapTaleSystem->>CapTaleSystem: state = PONG_CITY CapTaleSystem->>CapTaleSystem: if not enterPong set isPaused=false and pongState=GAME_ENEMY loop While state == PONG_CITY alt Player presses L Player->>CapTaleSystem: Request return to lobby CapTaleSystem->>CapTaleSystem: state = LOBBY and enterPong = false else Continue Pong scene CapTaleSystem->>PongCity: pongCity.update() alt pongState == GAME_ENEMY Player->>PongCity: Click AI or Human option PongCity->>PongCity: enemyUpdate() sets enemyState and next state else pongState == GAME_MENU Player->>PongCity: Press K N or R to choose level PongCity->>PongCity: gameLevel set and state = GAME_PLAYING else pongState == GAME_PLAYING alt Not paused Paddles->>Paddles: Update paddle positions from input or AI Ball->>Ball: Update ball movement and wall bounce PongCity->>PongCity: Check ball-paddle collisions and invert speed PongCity->>PongCity: Update scores and evaluate win/lose threshold else Paused Player->>PongCity: Press X to resume or R to reset end else pongState == GAME_WIN or GAME_LOSE Player->>PongCity: Press M for menu or R for replay PongCity->>PongCity: Transition to GAME_MENU or GAME_PLAYING end end end

4+1 View Model

Logical View

CapTaleSystem controls the application state. Cap stores player resources. Lobby routes the player into scene modules. The main city scenes are CustomCity, PongCity, CarCity, ATMCity, EarnCity, EnergyCity, and SpaceShooter. MessageManager supports user feedback, while Timer handles time-based behavior.

Development View

The project is organized around a single main.cpp entry point and a set of headers in headers/. Core files include cap.h, lobby.h, message.h, customCity.h, pongCity.h, carCity.h, atmCity.h, earningCity.h, energyCity.h, spaceShooter.h, sprites.h, custom_timer.h, settings.h, and spaceShooterSettings.h.

Process View

The runtime follows a single game loop. Each frame handles input, updates the active scene, processes collisions or timers, and renders the current screen. CapTaleSystem switches the active scene based on lobby selection or return-to-lobby signals from city modules.

Physical View

The system runs locally on a Windows desktop as a native Raylib-based C++ executable. All rendering, input, audio, and persistence occur on the same machine using local assets and the save file characterData.txt.

Scenarios

  • Entering a city from the lobby, paying any required token cost, and starting the selected scene.
  • Playing a city mini-game such as Pong, Car City, Earn City, Energy City, or Space Shooter.
  • Managing tokens and energy through ATM conversion, item collection, and lobby movement.
